# Hosted carousel agent

The hosted agent uses the official OpenAI JavaScript SDK against OpenRouter. Cloudflare Workflows checkpoints one model response or editing tool at a time. The loop has a configurable turn limit, checks cancellation between calls and before writes, and uses revision compare-and-swap to protect manual edits. It operates directly on the hosted project; the local MCP companion remains independent. CarouselBot arranges existing uploaded images, adds editable text, and edits slide layouts, crops and placement. It does not generate images or offer generative image editing.

Pi was evaluated: its agent core provides tool orchestration and its full coding agent now supports MCP. The full Cloudflare Pi integration runs in a Sandbox container. This editor needs a small set of application tools and Workflow checkpoints, so a provider SDK with a bounded loop avoids an additional container runtime or MCP bridge. See the [Pi agent core](https://github.com/earendil-works/pi/tree/main/packages/agent) and [Cloudflare Pi integration](https://developers.cloudflare.com/sandbox/guides/pi/).

The requested X check also found [Harrison Chase discussing provider prompt caching in Deep Agents](https://x.com/hwchase17/status/2043009699566494066) and [the pi-executor author describing a small MCP discovery interface](https://x.com/dinnaiii/status/2043809600546451738). These are design context; the provider and runtime documentation above determine this implementation.

`agent-model.mjs` creates drafts with the existing editor schema, normalized geometry and reusable pure helpers. The public tool boundary calls placed layers `images`; the stored document retains `overlays`. `agent-preview.mjs` opens a temporary Browser Run session, injects the private draft directly into the page, and imports the deployed editor renderer and font helpers. Uploaded assets are resolved through the user's authenticated store and converted to data URLs before injection. No public project preview URL is created. Each job reuses its own Browser Run session, whose ID is stored in existing job events. Every preview uses an isolated context; the context closes and the CDP connection disconnects after each call. Workflow resumptions reconnect only that job's saved session. The job closes its browser in a `finally` block; a two-minute idle timeout bounds cleanup after an interrupted process. See [Cloudflare session reuse](https://developers.cloudflare.com/browser-run/features/reuse-sessions/). Library IDs resolve through the current project's private asset references before image inspection.

OpenRouter sessions are pinned per user and project. The static prompt has an explicit cache boundary and Anthropic requests also enable automatic conversation caching. Usage includes the reported generation cost, cached tokens and cache-write tokens; the server debits each generation once. See [OpenRouter caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching).

Before a text request, a conservative input estimate and configured price ceilings determine the maximum output tokens. Image payloads count once as 20,000 vision tokens instead of encoded text bytes. When visual context exceeds the remaining budget, older image blocks are omitted while the latest image remains available for inspection; conversation text and stored history remain intact. Provider routing enforces the price ceilings. If billing data is absent after a successful provider response, or a model connection is lost before its billing result arrives, the remaining run reservation is accounted conservatively and the run stops. This prevents repeated calls from escaping the allowance. See [provider price limits](https://openrouter.ai/docs/guides/routing/provider-selection).


If a new job hits Browser Run's launch rate limit, it retries once after the Free plan's 20-second launch window, checking cancellation before the retry. Daily browser quota and full concurrency limits are returned immediately. This bounded recovery covers consecutive short jobs without sharing another job's browser or introducing a browser pool. See [Browser Run limits](https://developers.cloudflare.com/browser-run/limits/).

Configuration: `OPENROUTER_API_KEY` is a Worker secret. Optional variables are `OPENROUTER_MODEL`, `AGENT_MAX_TURNS` (18), `AGENT_MAX_INPUT_USD_PER_MILLION` (5), `AGENT_MAX_OUTPUT_USD_PER_MILLION` (25). `BROWSER` and the application's public `APP_ORIGIN` are required for rendering and text measurements. No fake provider is used in production; Node tests inject protocol fixtures and the browser gate exercises the real renderer.
